# Пул GPU-карт (0.7.11)

Студия **не спрашивает, какую карту использовать** — она спрашивает, **какая подходит прямо сейчас**.
Модуль `server/gpu-pool.mjs`; карточки `nvidia-smi --query-gpu=index,uuid,name,memory.total,memory.used,driver_version`
считаются картой пула, `freeMiB = total - used` (чужие процессы видны через used).

## Логика переключения

1. **Выбор — при спавне движка** (ComfyUI 8190, Pixal3D 8191, воркер TripoSG). Живой torch-процесс
   пересадить нельзя: `CUDA_VISIBLE_DEVICES` читается один раз. Поэтому choice sticky до выхода процесса.
2. **fit-first**: подходит карта, где свободной VRAM ≥ нужды движка (`ENGINE_VRAM_NEED_MIB`:
   pixal3d 10240 — замер этой ветки, hunyuan 6144 — SDXL-концепт, triposg 4096; переопределение
   `IMAGINARIUM_GPU_NEED_MIB_<ENGINE>`). Из подходящих берётся **самая маленькая**, при равенстве — самая
   пустая. Лёгкая работа не съедает большую карту.
3. **Нет свободной подходящей** — движок всё равно стартует на самой подходящей занятой
   (`free:false`), сериализация — per-card локом; **джоб в очереди ждёт** с текстом
   «Waiting for the GPU: …» и просыпается по событию освобождения + safety-тик 30 с.
4. **Локи per-card**: `IMA_GPU_RENDER_<UUID>` (UUID — стабильная идентичность, порядок индексов
   между бутами не гарантирован). Разные карты → два движка работают параллельно; одна карта →
   старый глобальный порядок. Нет `nvidia-smi` → нет пула: глобальный лок и нетронутый env, поведение до 0.7.11.
5. **handover только по общей карте** (`sharesCard`): разные карты — никакого `/queue` drain, `POST /free`
   и unload Ollama (минус 5–8 с на старт). Unknown-карта → полный handover (консервативно).
6. **RAM-гейт машины**: перед вторым параллельным движком свободная RAM должна держать порог
   `ram-check.mjs` (4096 MiB) — урок OOM-смерти node-процесса (два движка + Blender на 60 ГБ RAM).
7. **Очередь**: до `MAX_GPU_JOBS=2` джобов одновременно, но никогда два на одном движке и никогда
   два на одной карте. Все «неизвестные» факты (нет пула, движок запущен вне студии, карту не удалось
   вычислить) строго сериализуют как до пула.
8. **Настройка `gpuIndex` удалена** (0.7.10): карта выбирается, а не задаётся. Поле на диске
   ретейрится с одной честной строкой в warning, остальной конфиг грузится как ни в чём не бывало.

## Наблюдаемость

- `GET /api/gpus` (и `status.gpus`): пул, карты со свободной VRAM, какие движки какие карты держат,
  какие джобы идут/ждут и почему.
- job-запись: `gpuCard` пишется при диспатче; для hunyuan-джобов уточняется на момент взятия лока
  (ленивый старт движка); `pixal3d.gpuCard` — карта на момент завершения генерации.
  Стадия SDXL-концепта (общий 8190) **не** переписывает карту пиксела/трипосга — регресс
  найден живым прогоном.
- В карточке «Local 3D engine» строка `Hunyuan3D → …5070 · Pixal3D → …5060 Ti`, когда пул держит
  заявки; сам чип не меняется (он про «главный движок жив»).

## Что пул не обещает (v1)

Свободная VRAM проверяется **в момент диспатча**. Процесс извне, занявший память карты посреди
генерации, — единственная известная слепая зона (зафиксирована живым прогоном 2026-11-17: torch держал
5.4 GiB, карточка показывала ~10 — внешний хозяин). Студия не выгружает чужое; тексты про
«who holds the card» (ticket 37) продолжают называть процессы по имени.
