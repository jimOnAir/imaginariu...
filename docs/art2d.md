# 2D в AstraForge

Вкладка **«2D»**, CLI `scripts/art2d/art2d.mjs` и API `/api/art2d/*`. Всё локально: ComfyUI студии (:8190), веса с диска
`D:\ComfyUI\models`, обработка на CPU. Облако не используется.

То же, что студия делает в 3D, только картинками: персонаж по референсу → ракурсы → части тела для 2D-рига →
кадры анимации → лист спрайтов и `SpriteFrames` для Godot 4.5. Плюс эмоции, раскадровки, позы из 3D-клипов
и перерисовка готовых картинок в другом стиле.

## Движки

| id | Модель | Умеет | Лицензия весов | Скорость на RTX 4070 |
|---|---|---|---|---|
| `flux2` | FLUX.2 [klein] 4B, GGUF Q4_K_M + Qwen3-4B fp4 | текст → картинка **и рисование по 1–4 референсам** | **Apache-2.0** (с 0.6.6; коммерческое использование можно) | заметно быстрее прежней 9B — замеры ниже |
| `qwen` | Qwen-Image, GGUF Q4 | текст → картинка, читаемый текст на картинке | Apache-2.0 | ≈ 1,5–2 мин на 1 МП |
| `sdxl` | SDXL base 1.0 | быстрые черновики, image-to-image | OpenRAIL++-M | ≈ 20–30 с |

По референсу рисует только FLUX.2: персонаж, предыдущий кадр, поза и образец стиля подаются как отдельные
изображения (узел `ReferenceLatent`, схема из шаблона ComfyUI «Image Edit (Flux.2 Klein)»).
**FLUX.2 klein 4B — Apache-2.0** (с 0.6.6 заменил некоммерческую 9B): набор помнит лицензию
(`set.json → license`), экспорт кладёт `ASSET_INFO.txt`, интерфейс предупреждает только движки с
некоммерческими весами. Старые веса 9B, скачанные раньше, **остаются на диске и не трогаются** —
уведомление говорит об этом прямо; освобождать место решает сам пользователь.

**Установка у пользователей (с 0.4.7).** До 0.4.7 установщик не ставил ни весов FLUX.2 и Qwen-Image, ни узла GGUF —
у пользователей оба движка были серыми в списке «Движок» (жалоба 01.11.2026). Теперь это компоненты установщика `flux2`
(≈ 7 ГБ; до 0.6.6 — ≈ 16 ГБ из-за 9B) и `qwenimg` (≈ 23 ГБ): входят в «Полную», в мастере — отдельные вопросы, повтор — `Install.ps1 -Only flux2,qwenimg`.
Веса ложатся в `data\models\unet|text_encoders|vae` (адреса и sha256 — `installer\manifest.json`), узел `ComfyUI-GGUF`
(форк molbal, тот же коммит, что у владельца) — в `data\runtime\custom_nodes`, пакеты `gguf sentencepiece protobuf` — в Python
ComfyUI студии. `server/runtime.mjs` подключает эти папки в `models.yaml`. Без весов под списком движков пишется, чего нет и как поставить.

Для GGUF-весов в ComfyUI студии нужен узел `ComfyUI-GGUF` (у владельца лежит в `D:\ComfyUI\custom_nodes`):
`server/runtime.mjs` добавляет его в белый список. **После обновления перезапустите студию** (Stop.cmd → Start.cmd),
иначе статус покажет «нет узлов UnetLoaderGGUF».

## Рецепты

| Рецепт | Что получается | Референсы |
|---|---|---|
| `concept` | 1–4 варианта персонажа по описанию | — |
| `turnaround` | перед, 3/4, профиль, 3/4 сзади, сзади (вырезаны из фона) | персонаж |
| `parts` | 10 частей тела для 2D-рига: голова, торс, плечи, предплечья, бёдра, голени + `parts.json` (пивоты, родители) | персонаж |
| `animation` | ключевые позы действия: `idle walk run attack cast hit death jump`, направление `right left front front34 back` | персонаж, один seed на все кадры (`--chain` — ещё и предыдущий кадр) |
| `expressions` | 6 эмоций (портрет) | персонаж |
| `storyboard` | кадры 16:9 по строкам описания + лист раскадровки с подписями | персонаж (необязательно) |
| `poses3d` | персонаж в позах картинок-поз (кадры 3D-клипа из «Спрайтов» или `render_sprites`) | персонаж + поза |
| `restyle` | каждая картинка перерисована в выбранный стиль с той же композицией | картинка |

Стили (`art2d_styles.mjs`): рисованное фэнтези, аниме/cel, мультяшный, чиби, тёмное фэнтези, sci-fi, скетч тушью,
плоский вектор, пиксель-арт, пиксель-арт HD, «как на референсе». Пиксельные стили после генерации проходят
**настоящую пикселизацию** (`art2d_post.py`: box-уменьшение, палитра 24/48 цветов, nearest-увеличение; рядом `_1x.png`
в родном размере) — нейросеть сама пиксельную сетку не держит. Вместо стиля можно дать **образец стиля** (картинку).

## Что лежит в наборе

`data/art2d/<id>/`: `set.json` (рецепт, стиль, движок, лицензия, итоговые промпты, seed и время каждого кадра),
`refs/`, `raw/` (что нарисовал движок), `cut/` (вырезано из фона: белый ключ по краю + маска u2net), `px/`,
`out/sheet.png + sheet.json`, `out/board.png`, `out/parts.json`, `out/godot/<имя>/`.

Лист спрайтов: все кадры масштабируются **одним** коэффициентом (кадры сохраняют относительный размер), ноги на якоре.
Пресеты: `default` 256×256, `heroes_gates` 320×320 с якорем 160,272 (контракт «Врат», `references/games.md` §2), `hd` 512×512.

Экспорт «Для Godot» (кнопка или `art2d.mjs godot <id>`):
* анимация / позы → `sheet.png` + `<действие>.tres` (`SpriteFrames`, AtlasTexture на каждый кадр, fps и loop из действия);
* части тела → `parts/*.png` + `character_cutout.tscn` (Node2D → Sprite2D по иерархии, offset из пивота).
  Части стоят в точке сустава родителя — положение один раз правится в редакторе Godot (Bone2D/Skeleton2D — этап 3);
* остальное → PNG + лист.

## CLI

```
node scripts/art2d/art2d.mjs status                    # какие движки готовы на ComfyUI студии
node scripts/art2d/art2d.mjs styles | recipes | list
node scripts/art2d/art2d.mjs make --recipe turnaround --character hero.png --style painted
node scripts/art2d/art2d.mjs make --recipe animation --action walk --direction right --character hero.png --style pixel --sheet heroes_gates --godot
node scripts/art2d/art2d.mjs make --recipe poses3d --character hero.png --poses <папка кадров 3D> --style cel
node scripts/art2d/art2d.mjs make --recipe storyboard --scenes scenes.txt --character hero.png --style ink
node scripts/art2d/art2d.mjs make --recipe concept --engine qwen --prompt "..." --frames 3
node scripts/art2d/art2d.mjs redo <id> walk_03 --new-seed   # перерисовать кадр
node scripts/art2d/art2d.mjs resume <id>                    # продолжить после ошибки / отмены
```
`--comfy URL` — другой ComfyUI (по умолчанию `ASTRA_COMFY_URL` или :8190), `--root` — другая папка наборов, `--dry` — только показать промпты.

## Связь с 3D

* Кадр 2D → **«в 3D»** (кнопка на кадре): становится концептом во вкладке «Создать» → ракурсы → Pixal3D.
  Ракурсы `turnaround` можно сразу положить в «Ракурсы» как свои файлы.
* 3D → 2D: кадры клипа из «Спрайтов»/`render_sprites` → рецепт `poses3d`. Позы точные (их задаёт 3D-клип),
  рисовка — в 2D-стиле. Это самый надёжный путь к ровной анимации.

## Честно об ограничениях

* Кадры анимации из одного описания позы — не покадровая анимация художника: возможны скачки деталей между кадрами.
  Один seed на все кадры держит манеру рисунка; сверка с предыдущим кадром (`--chain`) держит детали, но FLUX.2 склонен
  повторять предыдущий кадр — поэтому по умолчанию выключена. `poses3d` убирает скачки почти полностью. Плохой кадр — «перерисовать».
* Части тела рисуются по отдельности: стыки (плечо/торс) приходится подправлять; пивоты — разумные значения по умолчанию.
* Вырезание рассчитано на светлый однотонный фон, который мы сами просим в промпте.
