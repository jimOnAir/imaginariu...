# Ошибки установки и запуска Imaginarium — журнал

Что сюда пишется: каждая ошибка, которая пришла от пользователей (отчёты на сервере ключей `keys-server/data/reports/<день>/`,
команда `node keys-server/keys-server.mjs reports`) или нашлась при проверках. По каждой: **что видит человек**, **причина**,
**что сделано**, **в какой версии**, **что осталось**. Новые записи — сверху. Ведёт тот, кто разбирает отчёт (решение владельца 01.11.2026). Всё присланное (логи, ссылки, код) сначала проверяется на вредоносное — правило в `docs/product/installer-security.md`.

Коды curl, которые встречаются в отчётах (установщик теперь сам пишет расшифровку рядом с кодом):

| Код | Что значит | Обычная причина |
|---|---|---|
| 6 | адрес сайта не найден | нет интернета, не работает DNS |
| 7 | не удалось подключиться | сайт недоступен или заблокирован в этой сети |
| 18, 56, 92 | соединение оборвалось при передаче | нестабильная связь (загрузка продолжается с того же места) |
| 22 | сайт ответил ошибкой (404/403) | файла больше нет по адресу — править `installer/manifest.json` |
| 28 | слишком долго нет данных | очень медленная связь |
| 33 | сайт не умеет докачивать с места обрыва | повтор после обрыва просит «продолжить», а сервер (actionforge.app) так не умеет — надо качать заново |
| 35 | защищённое соединение не установилось | сеть или антивирус не дают проверить отзыв сертификата (см. ниже) |
| 60 | сертификат не прошёл проверку | прокси или антивирус подменяют сертификаты |

## 02.11.2026 (день) — после «Полной» установки ярлык пишет «Node.js was not found» · исправлено в 0.4.14
- **Что видит человек:** установка в `D:\Imaginarium` закончилась словами «что-то не скачалось»; ярлык Imaginarium падает на
  `scripts\Start.ps1:19` — «Node.js was not found. Run ‘Установить Imaginarium.cmd’ in the application folder.» (комментарий пользователя).
- **Отчёт:** не пришёл ни один — ни от Setup.exe (он шлёт отчёт сам, без студии), ни пинг студии; с 10:46 до 12:00 Бали отчётов нет,
  среди всех отчётов папки `D:\Imaginarium` нет. Значит, отчёты выключены, сеть не пускает к keys.dops.media или это старый Setup.
- **Причина (предположение):** не скачался Node.js с nodejs.org (без него не ставятся и зависимости npm), Start.ps1 его не находит.
  Шаг «node» в 0.4.13 на чистой папке проходит — у нас nodejs.org доступен. Своих запасных адресов у Node.js нет (у Blender есть с 0.4.13).
- **Что сделано (0.4.14):** у Node.js 4 запасных зеркала (npmmirror, Huawei, Tencent, Aliyun — проверены 02.11, тот же файл
  35 574 076 байт) и sha256 из официального SHASUMS256.txt; `InstallNode` качает через `DownloadMirrors`. `Start.ps1` ищет Node.js
  ещё и в `runtime\node\node.exe` (если `config\paths.json` не сохранился), забытый путь разработчика убран, а вместо красной
  трассировки PowerShell пишет по-русски, чего не хватает и что сделать (Node.js, библиотеки npm, интерфейс, занятый порт, сервер не
  ответил). Порт берётся из `PORT`, как у сервера. Тесты: `tests/start-launch.test.mjs`, `tests/install-download.test.mjs`.
  Вживую: битый основной адрес → npmmirror, 6 с, сумма сошлась.
- **Осталось:** почему не пришёл отчёт Setup.exe, не выяснено; узнаем из install.log пользователя.
- **Людям сейчас:** запустить «Установить Imaginarium.cmd» в `D:\Imaginarium` — докачает недостающее; не вышло — прислать
  `D:\Imaginarium\installer\install.log` на support@dops.media.

  он найдёт Blender и доставит анимации.

## 01.11.2026 (вечер) — «PyTorch — ошибка (код 2)», за ней не ставятся ComfyUI и MV-Adapter · исправлено в 0.4.13
- **Что видит человек:** «Не всё установилось (comfy, mvadapter …)». Без ComfyUI не работают 3D по картинке, виды и 2D.
- **Отчёты:** 5 установок за вечер 01.11 (0.4.10–0.4.12; RTX 2060 SUPER, GTX 1050 Ti, RTX 4060 Ti, RTX 3090, RTX 3080 Ti). Самая
  частая ошибка за двое суток. Плюс 0.4.11 на RTX 5080: Python для ComfyUI — та же «код 2» и `No module named 'numpy'`.
- **Причина:** PyTorch для видеокарт — файлы около 3 ГБ с `download.pytorch.org`. `uv pip install` ждёт ответа сервера 30 секунд и
  делает 3 повтора; у этих людей сервер PyTorch отвечал медленно или соединение не устанавливалось: `Read timed out (read timeout=15)`,
  `Failed to fetch … download-r2.pytorch.org … client error (Connect)`. После этого `uv` сдаётся, и всё, что зависит от PyTorch, не ставится.
  Строка «Не удаётся привязать аргумент к параметру Path … NULL» — следствие: шаг MV-Adapter ищет Python ComfyUI, которого нет.
- **Что сделано (0.4.13):** `uv` ждёт ответа 300 с вместо 30, делает 10 повторов вместо 3 и качает по 4 файла, а не по 50
  (`UV_HTTP_TIMEOUT`, `UV_HTTP_RETRIES`, `UV_CONCURRENT_DOWNLOADS` в `Uv`); каждый шаг `uv` (Python, PyTorch, библиотеки ComfyUI,
  GGUF, MV-Adapter) при сбое сети повторяется ещё 2 раза с паузой 20 и 40 с (`Uvx`); не сетевая ошибка не повторяется. Вывод `uv`
  пишется в журнал, а первая строка ошибки и причина — в текст ошибки, то есть в отчёт. У pip (Pixal3D) таймаут 120 с и 10 повторов.
  MV-Adapter без ComfyUI — понятное сообщение. Мастер больше не забивает хвост отчёта полосами загрузки Ollama и curl.
  Тесты: `tests/install-download.test.mjs` (подставной uv: таймаут → повтор; 3 сбоя → причина в ошибке; ошибка зависимостей — без повтора).
- **Осталось:** если провайдер совсем не пускает к download.pytorch.org (Cloudflare R2), повторы не помогут — нужна своя копия
  PyTorch (например, на Hugging Face). Решать по новым отчётам: теперь в них видна причина.
- **Людям сейчас:** запустить «Установить Imaginarium.cmd» ещё раз (докачает только недостающее); часто проходит со второго раза.

## 01.11.2026 — все загрузки падают с кодом 35 · исправлено в 0.4.12
- **Что видит человек:** установка проходит до конца, но не ставится почти ничего: «Не всё установилось (node, blender, comfy, hy2, …)».
  В журнале на каждом файле: «связь оборвалась (код 35)… попытка 4 из 4», затем «Загрузка не удалась … (код 35)».
- **Отчёты:** 2 человека за вечер 01.11 (0.4.6 «Быстрая», en-US; 0.4.11 «Полная», RTX 4070 Laptop, ru-RU). Падали все сайты подряд:
  nodejs.org, blender.org, github.com, huggingface.co, ollama.com, actionforge.app — значит, дело не в сайтах, а в компьютере или сети.
- **Причина:** системный curl Windows работает через Schannel и перед загрузкой проверяет, не отозван ли сертификат сайта
  (запрос к серверам OCSP/CRL центра сертификации). Если сеть, прокси, провайдер или антивирус (HTTPS-проверка) не пропускают этот
  запрос, Schannel обрывает соединение: `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`, curl отдаёт код 35. Точного текста ошибки в
  этих отчётах нет: до исправления установщик сохранял только код.
- **Что сделано:** после первого кода 35 установщик повторяет загрузку с `--ssl-no-revoke` и дальше качает так всё (флаг
  передаётся и генераторам VFX через `IMAGINARIUM_CURL_NO_REVOKE`). Сертификат и цепочка доверия по-прежнему проверяются — пропускается
  только запрос об отзыве; веса моделей дополнительно сверяются по sha256 из манифеста. Текст ошибки curl теперь пишется в журнал и
  уходит в отчёт, у каждого кода — расшифровка. Тест: `tests/install-download.test.mjs` (подставной curl ведёт себя как Schannel).
- **Осталось:** если у человека код 35 и без проверки отзыва (антивирус рвёт TLS или сайт заблокирован), новый отчёт покажет точный
  текст curl — тогда разбирать отдельно. Этим двоим — новый установщик поверх в ту же папку, уже скачанное не качается заново.

## 01.11.2026 — студия не запускается после «Полной» установки · исправлено в 0.4.11
- **Что видит человек:** установка прошла, но студия не открывается: окно сервера закрывается сразу, страница не грузится.
- **Отчёт:** 0.4.6, RTX 3080 Ti, профиль full, `kind: crash, stage: server`: `SyntaxError … at readJson … index.mjs:32`.
- **Причина:** установщик записывал настройки помощника `data\config.json` командой `Set-Content -Encoding UTF8`; Windows PowerShell 5.1
  при этом ставит в начало файла невидимую метку BOM, а `JSON.parse` в Node на ней падает. Касается всех, кому установщик поставил
  помощника (Ollama). То же с `config\paths.json`: путь Pixal3D из него студия молча теряла.
- **Что сделано:** студия срезает BOM при чтении (`server/storage.mjs → readJson`), установщик пишет JSON без BOM (`WriteJsonFile`).
  Тест: `tests/json-bom.test.mjs`. Вживую: старый код падает с той же ошибкой, новый запускается.
- **Осталось:** у кого студия уже не запускается, сама обновиться не может — только новый установщик поверх.

## 01.11.2026 — компьютеры без видеокарты NVIDIA · исправлено в 0.4.7
- **Что видит человек:** ставит «Полную», качает около 41 ГБ, а 3D по картинке и генерация картинок не работают.
- **Отчёты:** 2 установки 0.4.6 без NVIDIA (вероятно AMD): `nvidia-smi` не найден.
- **Причина:** модели формы и картинок считаются на CUDA, без NVIDIA они не работают; установщик об этом не предупреждал.
- **Что сделано:** предупреждение до загрузки с названием видеокарты и облегчённый набор `lite` (≈ 3 ГБ); докачка после обновлений
  этот набор не ломает.

## 31.10.2026 — установка «висит на 5 %» · исправлено в 0.4.6
- **Причина:** проверка компьютера запускала `ollama list`, тот поднимал Ollama в трее и держал вывод; полоса не двигалась внутри шагов.
- **Что сделано:** Ollama опрашивается без запуска, полоса движется внутри загрузки, зависшая загрузка продолжается с того же места.
