## 2. Что нельзя трогать

- **ComfyUI на 8188 (`D:\ComfyUI`, пользовательский)** и Ollama не останавливать и не перенастраивать. Студия запускает **свой** процесс на 8190 из того же кода/`.venv`, но с отдельными каталогами,
  `--disable-all-custom-nodes` и белым списком (`ImaginariumMesh`, `ComfyUI-MVAdapter`). `Stop.cmd` убивает только Python с `data\runtime\input` и `--port 8190` (и Pixal3D с `data\runtime\pixal3d-temp`).
- Не терять `data\runtime\custom_nodes\ImaginariumMesh\__init__.py`; не удалять `data\` (проекты, модели, подключения); `data\vault.json` (DPAPI) — секрет, не в архивы и не в git.
- **Замок видеокарты `Global\HG_GPU_RENDER`** общий с пайплайном «Врат» (`tools\art\gpu_run.ps1`): рендеры игр, Blender-шаги на GPU и генерации идут по очереди. «Ожидаю освобождения видеокарты» — норма (до 60 мин, потом ошибка «Видеокарта занята другим процессом дольше 3600 с»).
- Платные облака (Tripo, Meshy), загрузка моделей и пакетов — только по решению владельца; Mixamo — только руками владельца.
- Neon Flames (VFX) без лицензии — в продаваемую сборку не включать. Модели Hunyuan3D нельзя использовать в ЕС, Великобритании и Южной Корее.

## 3. Установка и запуск

| Симптом | Причина / решение |
|---|---|
| Мастер зависает на вопросе | он интерактивный: используйте `-Yes -Only …` (ответы по умолчанию; `hy21`, `sdxl`, `vfx`, `pixal3d` без `-Only` не поставятся) |
| `clips` падает «Нужен Blender» | порядок в `-Only`: `blender` раньше `clips` |
| `mvadapter`: «SDXL ещё не скачан» | поставьте `sdxl` (6,9 ГБ) раньше; после — перезапуск студии (`Stop`, `Start`): белый список узлов читается при старте ComfyUI |
| «Port 3210 is in use by another application» | на 3210 чужое приложение; `PORT` меняет только сервер/CLI, а `Start.ps1`/`Stop.ps1` зашиты на 3210 |
| «Порт 8190 занят другим ComfyUI» | чужой ComfyUI на 8190; освободить порт или подключить его адрес в «Подключениях» |
| Порт 3211 занят (`EADDRINUSE`) | `IMAGINARIUM_VFX_WEB_PORT` |
| «Node.js was not found» / «Dependencies are missing» / «The interface has not been built» | нет Node ≥ 22.12, `node_modules\express` или `dist\index.html` → компоненты `node`, `npm` мастера |
| ComfyUI студии не поднимается сам | сервер автозапускает его, только если `data\models\checkpoints\hunyuan3d-dit-v2.safetensors` лежит именно там (а не только в `D:\ComfyUI\models`) → «Подключения → запустить 3D-движок» (`POST /api/runtime/start`); лог `data\runtime\comfy.log` |
| «Сервер студии ещё не знает маршрут …» | студия запущена до обновления кода → `Stop.cmd`, `Start.cmd`; либо `--direct` в CLI |
| Модуль «Кузница» «не подключён» | `/api/forge` отвечает не JSON: старый сервер; перезапуск |
| `forge.mjs --direct` / `views_*.mjs` не видят Blender, Godot, Pixal3D | они читают **только** переменные `IMAGINARIUM_*`, не `config\paths.json` (его читает `Start.ps1`); задайте `IMAGINARIUM_BLENDER`, `IMAGINARIUM_GODOT` (мастер ставит Godot в `runtime\godot`, а код ищет его только по `IMAGINARIUM_GODOT` и в `C:\Program Files\Godot`, `C:\Godot`, `C:\Dorn\Game Dev`, `%LOCALAPPDATA%\Programs\Godot`) |
| Чат «AI» не отвечает на новом ПК | (вывод из кода, не проверялось) в `server\schema.mjs` модель по умолчанию `qwen3-27b-cc:latest`; если её нет в Ollama — поставить `llm` мастером (он пропишет `data\config.json`) или выбрать модель в «Подключениях»; Ollama должна быть запущена |
| Не запускается ни одно задание | очередь ≤ 4; LLM-ответ и 3D взаимоисключают друг друга (одна видеокарта) |
| Пакет Setup.exe «защитил компьютер» | файл не подписан → «Подробнее» → «Выполнить в любом случае» |
| Полный прогон мастера «для проверки» | **не делать**: он переписывает ярлык рабочего стола и открывает студию; только `-ScanOnly`/`-DryRun` |

## 4. Pixal3D

- **DINOv3** — только из официальной копии `timm/vit_large_patch16_dinov3.lvd1689m` с преобразованием `tools\dinov3_timm_to_hf.py`; закрытый facebook-репозиторий и сторонние перезаливки не нужны. Автоскачивание DINOv3 со стороннего зеркала в узле отключено правкой `IMAGINARIUM PATCH` (`installer\pixal3d\patch_trellis2.py`).
- **utils3d** — только `github.com/EasternJournalist/utils3d` (1.7). Пакет с этим именем на PyPI — чужой.
- **meshlib** (некоммерческая лицензия) не ставится; дыры заделывает CuMesh (MIT). **nvdiffrast/nvdiffrec_render** (некоммерческие) стоят, потому что узел их импортирует, но студия их не вызывает: в графе не должно быть узлов `Texturing`, `Rasteriz`, `Render`, `UnWrap`, `nvdiff` — не использовать текстурирование Trellis2/Pixal3D.
- Нужно ≈ 10 ГБ свободной видеопамяти (пик над базой: 4 вида 9,5–10,8 ГБ, 1 вид 6,4 ГБ). Если её держит Blender, браузер с WebGL или игра — «не хватило видеопамяти». Два движка (Pixal3D и Hunyuan) одновременно не работают: студия сама выгружает чужой.
- Первый запуск 1–2 минуты (холодные кэши), потом ≈ 6 с; отмена задания может занять до минуты (останов на границе узла).
- **Сетки Pixal3D бывают рваными** (скелет: 161 кусок, открытые края). Без `voxel_remesh_m: 0.004` в `cleanup` `rig_humanoid` не раздаёт веса, и модель застывает в T-позе. **Но на целой сетке ремеш вредит**
  (лучник 16.10: после `cleanup` с 0,004 и 12 тыс. треугольников остались одни ремни без тела, а `result.json` был «ok»). Ремеш — только для рваных; после `cleanup` **смотреть превью** (связность и объём), не статус.
- Бюджет тонких сеток (скелет) — 24 тыс. треугольников: при 10 тыс. наруч становится кубиком, пальцы — пластинами. Для людей с лицом `target_tris` ≈ 24 000.
- После рига: `smooth_arm_weights.py`, `arm_rigid.py` (наруч жёстко на предплечье, кисть целиком) — иначе «шипы» и кривые наручи. Если риг отказался (несимметричные руки) — поставить `params.markers` (зеркало верной руки);
  авториг принимает T-позу за «руки вниз», `build_unit.sh` сам подставляет маркеры рук (`arm_markers.py`).
- Pixal3D строит ТОЛЬКО форму: цвет даёт `paint_from_concept` (по видам спереди и сзади; спину красит `paint_back.py`, шаг красит её только «насквозь»).
- Один вид хуже четырёх (IoU 0,89/0,71/0,86/0,73 против 0,97/0,94/0,94/0,94); для финального персонажа — ракурсы. Проверено на гуманоиде в T-позе; четвероногие и предметы не проверялись.

## 5. Ракурсы

- Вход — вид спереди в **T-позе, без оружия** в руках (оружие путает боковые виды). Персонажи не в T-позе, четвероногие и предметы не проверялись.
- «Слева» = камера со стороны левой руки персонажа (он смотрит к левому краю кадра). MV-Adapter: азимут 90° = «слева», 270° = «справа». На симметричном персонаже перестановка слева/справа результата почти не меняет.
- MV-Adapter: ≤ 640 px при 4 видах на 12 ГБ; 768 px — видеокарта уходит в подкачку (не использовать); 6 видов только в 512; детали сзади придумывает (на ополченце ошибся) — для черновиков и работы без сети. ChatGPT — чистовик (≈ 60 с на вид), но картинка уходит в OpenAI и нужна подписка и приложение Codex.
- `views_generate.mjs --status` → `codex.available` и `mvadapter.ready` должны быть `true`; `mvadapter.ready=false`: нет весов, нет `sdxl-config` (`scripts\views\make_sdxl_config.py`) или ComfyUI запущен до установки узла.
- `codex.exe` не в PATH — ищется через `Get-AppxPackage OpenAI.Codex`. Картинки «через GPT» — скилл `codex-image` (около 45–65 с на картинку), `openai-visual` без API-ключа не работает.

## 6. Риг, клипы, осанка, оружие

- **Осанка.** Клипы Quaternius после `retarget` разворачивают ключицы назад на 31–44° («плечи слишком повёрнуты назад», потом «руки в таз»). Поправка `posture.py`: ключицы к покою +6°, плечо доворачивается обратно (направление руки не меняется,
  иначе кисти уходят к тазу), висящая рука +4° вперёд; **поднятую руку (> 35°, стойка заклинателя) не трогать**. Ворота по всем клипам: кисти снаружи бёдер и не перед тазом, ключицы в стойке ≤ 18°, в ходьбе в среднем ≤ 15°.
  Провал — рендер не запускать. Призрака — `--floating`.
- **Клипы Quaternius/ActionForge** в библиотеке «на месте» (кость `root` обнулена; иначе удар уносил на 2,5 м вверх; оригиналы — `animations\_backup_quaternius_rootmotion`). Удар мечом — `quaternius-sword-attack` (без подскока; `regular-c` — прыжок);
  стойка — `quaternius-idle-loop` (у клипа лучника ноги слишком широко). Перед переносом — `clip_audit.py` (подъём таза). **Удар в прыжке (Mixamo Power Slash) владелец отменил.**
- Mixamo: FBX Binary, **Without Skin**, 30 к/с. Сборки с 12 к/с при ключах Mixamo 30 к/с дают вязкие анимации — экспортировать с fps=30. Нужные клипы библиотеки Mixamo (бег, прыжки, стрейфы, эмоции) отсутствуют — скачивает владелец.
- **«Оружие приклеено»**: нужен скелет с пальцами (Quaternius, 65–71 кость); хват оружия — расчётом (`grip_solve.py`: остриё = +Z грипа); щит — `attach_prop` с `fit: frame`, `standoff 0.03`, каплевидный `rot_deg [0,45,0]`; пальцы у low-poly слиты — `fist.py` гнёт кулак.
  Вырезанные предметы (`extract_props`) возвращает `attach_prop` с `extracted:true`; не прошедший проверку предмет заменяется предметом набора.
- `rig_humanoid` отказывает: «модель не похожа на человека», «руки асимметричны», разрывы сетки (`deform_torn_area` > 1 %). Пакет концептов идёт в режиме `--qa clips`: `deform_gate: warning`, решают разрывы на настоящих клипах в `motion_style` (1 % основное, 8 % руки над головой, 4 % мантия).
  Мантии рвутся (`robe: true` отрывает носок сапога у некоторых сеток — проверять), подол — `fix_weights.py`. Скелеты (Скелет, Скелет-лучник, Низший служитель) — только на основе скелета-воина C01 (решение владельца).
- Сломанные меши: «вплавленный» клинок (`tools/fix_fused_sword.py` в проекте фильма), меч-«брусок» заменяется. Крылья: сложенные, свои кости и взмах (`wing_flap.py`), раскрытые Hunyuan лепит пластинами.
- Локальная проверка `qwen3-vl:8b`: короткие вопросы да/нет, `think:false`, **`num_ctx` 16384** (по умолчанию 4096 — ответ пустой). Её ответ — подсказка; главное — цифровые ворота.

## 7. Экспорт и Godot

- Только Godot **4.5.1**; в среде есть и 4.7.x — ей проекты не обновлять. Если в HG «Nonexistent function … in base 'GDScript'» — не обновлён кэш классов: `Godot_…_console.exe --headless --editor --quit --path .`.
- Импортёр Godot 4.5 снимает метки `loop`/`cycle`/`loop_mode` с имени клипа по очереди и переименовывает от исходного имени → `pitch_cycle-loop` даёт «Animation not found». `godot_package` переименовывает такие клипы сам (`clip_renames`, `clips[].package_name`).
- Сокеты ищутся по `extras.game_socket`, а не по имени узла (импортёр `gltf/naming_version=2` заменяет точки); имена ASCII snake_case. `pivot_yaw`/`pivot_pitch` — не сокеты.
- GL Compatibility (оба целевых проекта) не поддерживает следы частиц (`trail_enabled`); `engine_trail` — крупные полупрозрачные частицы в мировых координатах. Масштаб FX — эвристика (`fx_auto_scale`); частица < 1 % длинной оси ассета — предупреждение `fx_scale_vs_asset`.
- Проверка Godot без окна не оценивает картинку: загрузка, имена, петли, масштаб, прикрепление. Визуальное превью — `fx_preview` (окно ~3 с).
- EEVEE в Blender 5.0 не умеет ловец теней: тень в спрайтах только с `engine: CYCLES` (профиль HG делает Cycles сам, ≈ 0,6 с/кадр). Ячейка вылезла за 448 px — `cell_fit`, а не автопоправка; специфичные подгонки «Врат» (`correct_fit`) не перенесены.
- Неверные единицы модели ловятся **до** рендера (`min_body_px`, `max_cell_px`): `height_m` в параметрах. Нейросетевая геометрия мягкая — для крупных планов нужны параметрические детали (`bone_kit`, `item_kit`, `place_parts`).
- Цвет из картинки — проекция фото, не PBR; скрытая сторона — догадка или зеркало; 86,5 % IoU силуэта (пример некроманта) не значит точность анатомии — не выдавать подгонку за «точную копию».

## 8. Библиотека и данные

- Пути в паспортах **абсолютные** (`asset.json`, `v00N\version.json`, `result.json`): перенос библиотеки в другой путь ломает `from: latest` старых версий (кода пересчёта нет). Держите `C:\Imaginarium\library`.
- Версии не перезаписываются; удаление = перенос в `trash\`. `data\library.moved-2026-10-11` — остаток переноса, можно удалить.
- Два одновременных процесса на одной библиотеке: клипы ведёт замок библиотеки (одна задача `clip_library` за раз; «Файлы ассета заняты другой программой…» — подождать).
- `forge-concepts.mjs` резюмируемый (`forge-concepts.state.json`); `--direct`, пока студия держит старый реестр; результат смотреть по превью `previews\<имя>.png`, не по статусу.
