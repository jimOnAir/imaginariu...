# Самообучение AstraForge: как студия учится на каждом ассете

Студия AstraForge (скилл `astraforge`, приложение APP = `C:\Users\doron\Documents\Codex\2026-10-09\3\outputs\AstraForge`)
запоминает, как делался каждый ассет и что о нём сказали. Из этого она сама выводит **рецепт класса** — лучшие известные
параметры каждого шага для «зомби», «орудия», «здания» и т. д. — и **грабли** — наборы параметров и пути, которые уже
браковали. Следующий ассет того же класса стартует с рецепта, а не с умолчаний шага. Работает для любого пользователя
студии: всё лежит в его библиотеке. Устройство и формулы — `APP/docs/forge/LEARN.md`.

Твоя часть работы — **цикл из четырёх шагов**. Пропуск шага ломает обучение: без вердикта студия не узнаёт, что вышло.

## 0. Что где лежит

| Что | Где | Кто пишет |
|---|---|---|
| Журнал производства: каждый запуск шага — класс, параметры, что подставил рецепт, проверки `checks`, превью, время | `C:\AstraForge\library\learning\journal.jsonl` | сервер и CLI сами, после каждого шага; старые запуски — `learn sync` |
| Вердикты: принято / на доработку / брак, оценка 1–5, теги брака, комментарий, к версии (и шагу) ассета | `…\learning\feedback.jsonl` | «Приёмка» (обе вкладки), MCP `forge_feedback`, CLI `learn feedback`, API |
| Знания владельца: закреплённые рецепты, правила классов, заметки «путь / грабли / совет» | `…\learning\knowledge.json` | `forge_recipe_pin`, `forge_learn_note`, CLI `learn pin` / `learn note` |
| Сводка для людей и агентов | `ai/skills/astraforge/references/recipes.md` (генерируется), `references/quality-lessons.md` (уроки словами) | ты, на шаге 4 |

Журнал и отзывы только дописываются. Ошибочный вердикт исправляется новым (последний вердикт версии главнее; `cleared` — снять).

**Класс ассета** определяется так: класс запуска (`--class`, `assetClass`) → `profile.class` паспорта → правило по имени
(встроенные: `building` — `bld_*`, `house*`; `zombie` — `zciv_*`, `zomb*`, `z_*`; `weapon` — `weapon*`, `turret*`, `gun`…;
`vehicle` — `car_*`; `tree`) → вид ассета (`humanoid`, `creature`, `item`, `ship`, `prop`). Новому классу дай явное имя:
`forge create … --profile '{"class":"boss"}'`, или правило — `POST /api/forge/learn/classes {id, title, match, kinds}`.

## 1. ПЕРЕД заданием — прочитай рецепт и грабли (обязательно)

1. `forge_recipes` с классом ассета (MCP; или `node scripts/forge.mjs learn recipes --class zombie` из APP). Прочитай:
   - **Путь** (`route`) — чем этот класс делать. Если твой план расходится с путём — иди по пути или сначала объясни владельцу, почему нет.
     Пример: здания — процедурно `city_bldg.py` + `mesh_fracture.py --grid`, а не Pixal3D + `paint_from_concept` («фольга»).
   - **Грабли** — наборы параметров с браком, их отличие от рецепта и причина (теги, слова владельца). Такие наборы не повторять.
   - **Рецепт** шага и **закреплённые** рецепты (решения владельца; `*` — для всех классов).
2. Сверь с `references/quality-lessons.md` скилла `astraforge` — общие уроки приёмки (облёт с 8 сторон, глаза, кроны…).
3. Перед запуском посмотри, что подставит рецепт: `forge_plan` (или `learn plan <assetId> --steps f.json`). Рецепт заполняет
   **только те параметры, которых нет в шагах**; явные параметры и параметры пресета главнее, `profile` рецепт не меняет.
   Не вписывай руками параметры, которые даёт рецепт, — иначе студия не сможет улучшить их следующим ассетом.
   Отступаешь от рецепта сознательно — меняй один параметр явно и скажи владельцу, что проверяешь.

## 2. Работа

Запускай как обычно (`forge_run`, `forge.mjs run`, пачки игр). Ответ запуска содержит `learned` / `recipeNotes` — что пришло
из рецепта и с какого слоя (`zombie:journal`, `*:pinned`). Сравнить с умолчаниями шага — `recipes: false` (`--no-recipes`).
Правила студии из `astraforge` действуют: загрузки — с согласия владельца, ComfyUI 8188 и Ollama не трогать, видеокарта — по одной задаче.

## 3. ПОСЛЕ — сверь с концептом и запиши вердикт

1. **Смотри превью, а не только `checks`**: «Приёмка» → «Журнал и рецепты» или `forge_journal view=versions` (ссылки `previews`).
   Ставь рядом концепт или лист стиля игры. Зелёные проверки ≠ принято.
2. **Вердикт** — `forge_feedback {assetId, version, step?, verdict, rating?, tags?, comment}`:
   - `accepted` — совпадает с концептом; `rework` — близко, но есть конкретная правка; `rejected` — брак.
   - `step` — если дело в одном шаге (например `render_sprites`); без него вердикт относится ко всей версии, а теги сами
     указывают виноватые шаги (`acid_colors` → `render_sprites`/`paint_from_concept`, `foil` → `paint_from_concept`/`cleanup`…).
   - Теги из каталога: `acid_colors`, `washed_out`, `too_dark`, `outline`, `pixel_noise`, `off_cell`, `wrong_orientation`,
     `unlike_concept`, `foil`, `muddy_texture`, `extra_features`, `torn_mesh`, `bad_rig`, `bad_animation`, `prop_not_in_hand`,
     `wrong_scale`, `floating`, `other` — или свои слова.
   - Комментарий: **что** не так и **какой параметр** вероятно виноват («saturation 1,2 — кислотно рядом с листом»).
   - Пачка одним вердиктом — `targets: [{assetId, version}, …]` (API/MCP через `POST /api/forge/learn/feedback`).
3. **Чей вердикт.** `by: "owner"` — только для слов владельца (он сказал в чате «брак», «кислотно», «вот так хорошо» —
   запиши сразу, его словами). Свой вердикт пиши с `by: "claude"` и ставь `accepted` только после сравнения с концептом
   бок о бок; сомневаешься — покажи владельцу и спроси одним коротким вопросом. Вердикты владельцу не выдумывай.
4. **Урок не про параметры, а про путь** («Pixal3D-дома рушатся фольгой — делать процедурно») — `forge_learn_note`
   (`route` — рабочий путь, `pitfall` — грабли, `tip` — совет).
5. **Решение владельца о параметрах** («для мелких пиксель-спрайтов всегда так») — `forge_recipe_pin` (класс или `*`).
   Закреплять без решения владельца нельзя: закреплённый рецепт главнее журнала.

## 4. Периодически — сведи журнал в справочники

Когда: после пачки ассетов, в конце сессии с новыми вердиктами, раз в неделю.

1. `node scripts/forge.mjs learn sync` — дописать запуски, сделанные старым процессом студии.
2. `node scripts/forge.mjs learn digest --out ai/skills/astraforge/references/recipes.md` — рецепты, грабли, заметки по
   классам. Файл генерируется: руками не правь, перегенерируй.
3. Новые уроки словами — в `ai/skills/astraforge/references/quality-lessons.md` (таблица «брак | причина | как делать»
   в разделе класса). Только подтверждённые вердиктами или владельцем; ссылайся на рецепт класса.
4. Коротко — в Obsidian `C:\Dorn\DopsMedia\00 Dops Media\Проекты\astraforge-кузница.md`, раздел «Что сделано».

## Как студия считает рецепт (чтобы понимать, на что влияет твой вердикт)

- Запуски группируются по классу и шагу с профилем (`render_sprites@pixel`). В рецепт идут стиль и качество; клипы,
  размеры (`height_m`), пути, `asset_id`, `seed`, ссылки на ассеты — нет.
- Балл набора параметров: `accepted` +1, `rework` −0,5, `rejected` −1, оценка двигает на ±0,1 за звезду от 3;
  запуск, остановленный красными проверками без вердикта, −0,5. Последний вердикт версии главнее прежних.
- Рецепт — набор с наибольшим баллом, у которого есть хотя бы одно «принято» и балл > 0. Остальные с браком — грабли.
- Слои: `*` (закреплённый) → вид ассета → класс; на каждом уровне сначала журнал, потом закреплённое. Ключи более
  узкого слоя главнее. Подставляются только недостающие ключи, значения проходят проверку реестра шага.

## Команды

| Действие | MCP | CLI (`node scripts/forge.mjs …` в APP) | API `/api/forge` |
|---|---|---|---|
| рецепт и грабли класса | `forge_recipes` | `learn recipes --class c` | `GET /learn/recipes?class=c`, `GET /learn/digest` |
| что подставит рецепт | `forge_plan` | `learn plan <id> --steps f.json` | `POST /assets/:id/plan` |
| журнал | `forge_journal` | `learn journal` / `learn versions [--pending]` | `GET /learn/journal`, `GET /learn/versions` |
| вердикт | `forge_feedback` | `learn feedback <id> --verdict брак --tags … --comment …` | `POST /learn/feedback`, `POST /assets/:id/feedback` |
| закрепить рецепт | `forge_recipe_pin` | `learn pin --class c --step s --variant v --params '{…}'` / `--unpin` | `POST /learn/pin` |
| заметка класса | `forge_learn_note` | `learn note --class c --kind route --text "…"` | `POST /learn/notes` |
| догнать старые запуски | — | `learn sync` | `POST /learn/sync` |
| сводка | `forge_recipes format=md` | `learn digest [--out файл]` | `GET /learn/digest` |

Если работающая студия запущена со старым кодом (маршрута `/learn` нет) или выключена, CLI и MCP читают и пишут файлы
библиотеки напрямую; вердикт тогда попадает только в журнал, на карточку «Приёмки» — после перезапуска студии.

## Нельзя

- Выдумывать вердикты владельца или ставить `by: "owner"` своим оценкам.
- Закреплять рецепт без решения владельца.
- Писать тестовые отзывы в рабочую библиотеку `C:\AstraForge\library` — для проб бери временную (`ASTRA_FORGE_LIBRARY`).
- Править `journal.jsonl` / `feedback.jsonl` руками: строки только дописываются, ошибка исправляется новым вердиктом.
