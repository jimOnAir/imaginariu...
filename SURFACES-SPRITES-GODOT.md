# Текстуры, запекание и Godot

## Текстуры

Выберите модель → **Текстуры → Создать UV-атлас**. xatlas работает на CPU и переносит атрибуты, morphs и веса на вершины, дублируемые вдоль UV-швов. Перестройка UV требует повторного размещения прежних карт.

Затем можно создать Color / Roughness / Metallic / Normal из материала «Металл», «Камень», «Дерево» или «Ткань» с разрешением от 512 до 4096, загрузить собственные карты и рисовать по Base Color. Эти четыре основы процедурные, без нейросетевой генерации. Normal использует OpenGL-конвенцию.

**Запечь видимый цвет** переносит изображение выбранной стороны в единый UV-атлас. Используются направление нормалей и depth-buffer для отсечения скрытых поверхностей. Нужен референс, согласованный с позой и выбранным видом. Скрытые стороны сохраняют прежний цвет; для них добавьте другие ракурсы. Кнопка не восстанавливает неизвестные детали, не создаёт полную PBR-разметку из фотографии и не заменяет AI-текстурирование.

Кисть: ЛКМ — мазок, ПКМ / колесо — камера, Ctrl+Z — отмена мазка. PNG-карты скачиваются отдельным ZIP. Для сохранения материалов и ориентации карт вместе с моделью используйте GLB.

Проекты сохраняются как gzip JSON с текстурами и скелетом. Старые JSON-проекты продолжают открываться. Лимит распакованного проекта — 512 МБ; карты 4K и история отмен требуют больше RAM.

## Все анимации в GLB

Во вкладке **Спрайты** задайте FPS → **Запечь все в GLB**. Каждый клип вычисляется через AnimationMixer и записывается равномерными ключами position/quaternion/scale/morph weights, включая последнюю позу. Кости и веса сохраняются. Частицы рендерятся в спрайты и видео; произвольные VFX в GLB не переносятся.

## Изометрические спрайты

По умолчанию: **8 направлений, 35° над горизонтом, прозрачный фон**. Задайте размер, FPS, клипы, петли и включение эффектов → **Экспортировать PNG + Godot**.

ZIP содержит папку `ImaginariumSprites`: атласы PNG RGBA до 4096 px, `metadata.json` с прямоугольниками и pivot, `animations.tres`. Извлеките папку в корень Godot-проекта. У `AnimatedSprite2D` назначьте `animations.tres` как SpriteFrames. Например, `Walk_dir0` — первый ракурс, `Walk_dir1` — следующий через 45°. Нулевой ракурс снят камерой со стороны +Z; согласуйте соответствие направлений с ориентацией своего персонажа.

Для всех направлений используется единый кадр и масштаб; Root фиксируется для движения на месте. Bounding box оценивается по нескольким позам, поэтому экстремальные короткие движения требуют визуальной проверки. В metadata сохраняется pivot стоп; сам AnimatedSprite2D использует центр текстуры, его offset / позицию настройте по pivot. У циклов конечный дубликат не включается; у разовых действий последняя поза включена.

Экспорт ограничен 2048 кадрами и 180 млн пикселей за пакет. Для длинных клипов уменьшите FPS или выбирайте клипы по одному.

## Проверенные примеры

- `Godot-textured-baked-demo.glb`: 27 костей, 15 мешей с skin, Idle / Walk / ArmRaise, встроенные PBR-карты. Реальные изменения костей проверены Godot 4.7.2.
- `Godot-isometric-demo.zip`: 584 кадра 128×128, 3 атласа, 24 SpriteFrames-анимации. Прозрачность и отсутствие пустых кадров проверены по пикселям и в Godot.
- `Godot-sprite-preview.jpg`: контактный лист направлений. Это технический манекен для проверки pipeline.

Базовые походки — процедурные черновики без IK и контакта стоп с поверхностью. Их нужно исправлять для игрового персонажа. Нейросетевая геометрия также требует проверки силуэта, анатомии и бюджета сетки.
